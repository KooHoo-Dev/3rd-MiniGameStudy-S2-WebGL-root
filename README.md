# 미니게임 개발 스터디 S2 - WebGL
> **대상**: 유니티 개발자 양성과정 수강생
> **기간**: 총 5주
> **플랫폼**: Unity WebGL (브라우저 실행)

---
## 스터디 컨셉
시장에서 검증된 하이퍼캐주얼 게임 3종의 **코어 루프만 추출**하여, WebGL 기반의 **세션 5~15분짜리 미니게임**으로 재구성한다.

## 핵심 학습 목표

| 목표 | 내용 |
|---|---|
| **역설계 역량** | 상용 게임의 코어 루프를 분해하고, 무엇이 재미의 원천인지 식별한다 |
| **루프 확장 설계** | 30초~2분짜리 원본 루프를 5~15분 세션으로 확장하는 **상위 구조를 직접 설계**한다 |
| **WebGL 실전 대응** | 빌드 용량, 로딩, 입력, 성능 등 웹 환경 특유의 제약을 경험하고 해결한다 |

원본 3개 게임의 인게임(광고 모드)은 **전부 30초~2분 루프로 설계되어 있음.**
따라서 5~15분 세션을 만들려면 **원본을 그대로 옮기는 것으로는 불가능.**

> **이 스터디의 진짜 난이도는 "구현"이 아니라 "확장 설계"에 있음.**
> 짧은 루프를 무엇으로 감싸서 5~15분을 버티게 할 것인가? — 생각해볼 포인트

### 결과 목표

- **에셋/비주얼**: 자유. 코어 루프만 가져오고 테마는 본인이 정한다
- **광고 요소**: 넣지 않는다. 순수 미니게임으로만 완성
- **배포**: 브라우저에서 링크로 실행 가능한 상태

## 3. 과제 A — 게이트 러너 (원본: 라스트 워: 서바이벌)
> https://www.youtube.com/shorts/tmSbSsyZu6s

### 3.1 원본 코어 루프

플레이어가 유닛 무리를 좌우로 조작하며 전진한다. 경로 중간중간 `×2`, `+3`, `-5` 같은 **연산 게이트**가 배치되어 있고, 어느 쪽을 통과하느냐에 따라 유닛 수가 변한다. 
최종적으로 적 무리와 충돌해 수적 우위로 승패가 결정.

- **핵심 유저 경험**: 즉각적인 시각적 증식 + 0.5초 안에 내리는 산술 판단
- **원본 루프 길이**: 약 30~60초

### 3.2 5~15분 확장 설계 방향 (참고 예시)
- **연속 스테이지 구조**: 짧은 런을 8~12회 연속, 실패 시 그 시점부터 재도전
- **메타 성장 레이어**: 런 사이에 능력치를 강화 (유닛 기본 수, 특수 유닛 해금 등)
- **분기 경로**: 매 구간마다 위험/안전 루트 선택 → 리스크 vs 리턴
- **누적 자원 관리**: 게이트 통과로 얻은 유닛을 다음 구간에 어떻게 배분할지 결정

### 3.3 요구사항

**필수**
- 좌우 드래그/스와이프 입력으로 유닛 무리 이동
- 연산 게이트 4종 이상 (`+`, `-`, `×`, `÷`) 및 통과 시 유닛 수 반영
- 유닛 포메이션 자동 정렬 (수가 늘어나도 시각적으로 뭉개지지 않게)
- 적 충돌 → 수적 우위 판정 → 승/패 결과
- **오브젝트 풀링 적용** (유닛 수가 폭증하므로 필수)
- 5분 이상 플레이 가능한 상위 구조 (3.2 참고)

**추가**
- 유닛 수에 따른 시각/사운드 피드백
- 스테이지 진행도 및 스코어 UI
- 난이도 곡선 (후반 게이트가 더 위험해짐)
- 특수 게이트 (무기 변경, 유닛 타입 변경)
- 보스 구간
- 이 외의 본인이 직접 생각한 아이디어 등

## 4. 과제 B — 스택 서빙 (원본: 피자 레디)
> https://www.youtube.com/shorts/L9TTkwMW11o

### 4.1 원본 코어 루프

플레이어 캐릭터가 매장 안을 이동한다. 조리대에 다가가면 완성품이 **머리 위로 쌓이고(스택)**, 손님 테이블/카운터에 다가가면 스택이 하나씩 빠져나가며 돈이 들어온다. 번 돈으로 테이블 확장, 직원 고용, 설비 업그레이드를 한다.

- **핵심 유저 경험**: 물리적으로 쌓이고 줄어드는 스택의 촉감 + 눈에 보이는 확장
- **원본 루프**: 무한 Idle 구조 (자연 종료 없음)

### 4.2 5~15분 확장 설계 방향 (참고 예시)

원본은 무한 루프라 **오히려 "끝"을 만들어야 한다.**

- **목표 매출 달성형**: 15분 안에 목표 금액 도달 (타임 어택)
- **일자 진행형**: 1일 = 3분, 5일 완주 구조. 일마다 손님 수/요구 증가
- **압박 곡선**: 손님 인내심 게이지 도입 → 방치하면 이탈, 후반으로 갈수록 짧아짐

### 4.3 요구사항

**필수**
- 캐릭터 이동 (마우스/터치 드래그 또는 클릭 이동)
- **스택 시스템**: 아이템이 물리적으로 쌓이고 순차 소비 (최대 개수 제한 포함)
- 손님 **상태머신**: 입장 → 대기 → 주문 → 수령 → 퇴장 (+ 인내심 초과 시 이탈)
- 자원(돈) 획득 → 업그레이드 → 처리량 증가로 이어지는 성장 루프
- 명확한 **세션 종료 조건** (4.2 참고)

**추가**
- 업그레이드 3종 이상 (조리 속도, 스택 최대치, 테이블 추가 등)
- 스택 쌓임/소비 시 애니메이션·사운드 피드백
- 손님 인내심 시각화
- 직원 NPC 자동화 (플레이어가 안 해도 일부 처리)
- 메뉴 다양화 (여러 종류 스택 관리)
- 이 외의 본인이 직접 생각한 아이디어 등

## 5. 과제 C — 디펜스 (원본: 킹샷)
> https://www.youtube.com/watch?v=pl4FYO1T3Iw

### 5.1 원본 코어 루프

플레이어가 캐릭터를 직접 조작해 맵을 돌아다니며, 주기적으로 적이 몰려오고, 자동 사격으로 이를 방어한다. 모은 자원으로 방어 시설과 무기를 **실시간 업그레이드**한다.

- **재미의 원천**: 성장과 디펜스 사이클의 순환과 시간 압박
- **원본 루프**: 약 1~2분

### 5.2 5~15분 확장 설계 방향 (참고 예시)

- **웨이브 구조**: 웨이브 사이 자원 채집 페이즈(30초) → 방어 페이즈. 총 8~12웨이브
- **거점 확장**: 다양한 기믹을 가진 타워와 건물의 실시간 배치 및 거점 확장

### 5.3 요구사항

**필수**
- 캐릭터 이동 + **자동 사격** (가장 가까운 적 자동 타겟팅)
- 자원 채집 시스템 (채집 오브젝트 → 자원 획득)
- **웨이브 스포너** (시간/조건 기반 적 등장, 난이도 상승)
- 자원 → 업그레이드 → 전투력 상승 루프
- 방어 실패 조건 (거점 HP 등) 및 승/패 결정
- **오브젝트 풀링** (적, 투사체)
- 방어 시설 배치 (터렛)


**추가**
- 업그레이드 트리 3종 이상 (사거리, 공속, 데미지 / 채집 속도)
- 웨이브 예고 UI (다음 적까지 남은 시간)
- 채집 vs 방어의 시간 압박이 실제로 느껴지는 밸런싱
- 적 타입 다양화 (근접형, 원거리형, 탱커)
- 방어 시설의 다양화
- 이 외의 본인이 직접 생각한 아이디어 등
